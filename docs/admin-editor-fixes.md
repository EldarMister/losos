# Исправления административных форм

Дата проверки: 13 октября 2026 года.

Вызовы window.confirm внутри панели заменены единым Dialog шаблона с ролью alertdialog и кнопками «Нет» / «Да». По умолчанию фокус находится на «Нет». Escape отменяет действие, повторные клики не ставят новые действия в очередь. Выход завершает ожидающее подтверждение. При отказе от перехода назад сохраняются черновик и URL. Защита закрытия самого браузера остаётся стандартным beforeunload: браузер не позволяет заменить её модалкой страницы.

В карточке блюда вкладки и нижние кнопки находятся вне прокручиваемой области. Проверены длинные описание/состав на 1440×900 и 390×700: нижняя граница области полей совпадает с верхней границей footer, кнопки находятся внутри viewport. Уведомление о новом заказе остаётся под открытой модалкой и не перекрывает сохранение. На мобильном вкладки прокручиваются без широкой полосы прокрутки.

Фото категории можно заменить или удалить, в том числе автоматическую обложку из блюда. `categories.imageHidden` сохраняет явное удаление; после повторного открытия фотография блюда не подставляется снова. Миграция `1785013000000-AddCategoryImageVisibility` сохраняет прежнее поведение существующих категорий (false). Она зарегистрирована в CLI DataSource и AppModule; применяется штатным запуском backend. Новая обложка снимает этот флаг через форму. Публичный сайт также учитывает его. Фотографии самих блюд не удаляются.

Удаление города находится в меню действий и требует `cities.delete` вместе с правом просмотра. `DELETE /api/admin/regions/:id` удаляет только пустой город: последний город, города с заказами, собственными категориями/акциями/точками выдачи и источники контента других городов защищены ответом 409. Для рабочего города доступно «Скрыть». Создание, изменение источников и удаление сериализуются транзакцией; оформление заказа удерживает город до commit. Удаление выбранного города переключает панель на оставшийся город. Раздел городов не запрашивает ненужный каталог или статус EDU POS.

## Проверено

Все операции записи выполнялись на отдельной локальной базе `admin_redesign_test`, внешние интеграции отключены. Рабочие данные сайта для проверки не изменялись.

- Новая PostgreSQL suite: 9/9, включая зависимости, сохранение каталога/заказов, конкурентные удаления и назначение источника, checkout, удаление и замену фото после загрузки из БД.
- Security HTTP/PostgreSQL: 10/10, включая запрет удаления города менеджеру; reports/CAS: 10/10; notification integration: успешна.
- Backend unit: 57/57; city visibility: 1/1.
- Frontend: Next.js build, Vinext build + 8/8 HTML suites, TypeScript и ESLint прошли.
- Браузер: «Нет» сохраняет вариант и черновик, «Да» удаляет; Escape отменяет подтверждение; отказ при переходе назад сохраняет URL и ввод. Системных JS-диалогов в сценарии фото: 0.
- Браузер → API → БД: удаление автоматической обложки сохраняется, повторное открытие показывает загрузку фотографии; замена файлом сохраняет изображение и снимает флаг. Начальные значения тестовой категории восстановлены.
- Создание/выбор/удаление тестового города через UI: «Нет» сохраняет, «Да» удаляет из БД и списка; выбранный город становится Бишкек. После ограничения фоновых запросов ошибок HTTP в повторном сценарии не было.
