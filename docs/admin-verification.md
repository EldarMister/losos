# Проверка новой панели NAKTA

Дата: 12 октября 2026 года. Ветка: `codex/admin-redesign`. Исходное состояние до работ: `ba59446d`, заранее отправлено в `github/codex/pre-admin-redesign-20261012`.

## Окружение

- Windows, Chromium через Playwright; frontend `http://127.0.0.1:3102/admin`, API `http://127.0.0.1:4100/api`.
- Отдельный PostgreSQL 18 на localhost:55433, база `admin_redesign_test`. Интеграционные suites используют изолированные схемы и явный `TEST_DATABASE_URL`.
- Миграции применены только в тестовом окружении. Production не обновлялся, рабочая БД не пересоздавалась.
- Тестовые сотрудники и заказы помечены «ТЕСТ». Суммы на скриншотах — результаты сохранённых тестовых заказов, не реальные бизнес-показатели. В рабочем интерфейсе и отчётах встроенных демонстрационных данных нет.
- Test harness отключает исходящие запросы к кухне, SMS и другим внешним интеграциям. Статусы preparing/completed начальных fixtures заданы явно; это не проверка реальной отправки на кухню.

## Границы проверки и выпуск

- Реальная Web Push-доставка через службы браузеров, установка на физическое устройство и запуск из системной иконки не выполнялись. Нужны staging HTTPS, VAPID, разрешения и проверка на целевых устройствах. Проверены manifest, installability, регистрация, offline и обновление worker.
- Живые операции EDU POS, SMS, геокодирование и карты не запускались; их существующие адаптеры сохранены. Перед выпуском нужен отдельный прогон с разрешёнными внешними учётными данными.
- Возвраты, себестоимость и старая история действий отсутствуют в исходном учёте; их значения не выдумываются. Новые audit/category snapshots собираются после миграций.
- У исторических дат заказов тип `timestamp without time zone`. Формулы и требование согласовать Node/DB TimeZone описаны в [инструкции](admin-redesign.md). Общий CRUD-аудит выполняется после успешной операции; он не атомарен с каждой бизнес-мутацией.
- Сборки проходят, однако аудит зависимостей показал существующие уязвимости дерева пакетов. Автоматическое обновление несовместимых зависимостей через force не выполнялось; это отдельная задача перед публичным выпуском.
