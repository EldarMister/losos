# Новая административная панель NAKTA

## Основа и совместимость

Использован установленный пользователем репозиторий `C:\Users\User\Desktop\admin`, версия `nextjs-version`, commit `953300fa5176608a9d682943edfc359ce809f2c7` из https://github.com/shadcnstore/shadcn-dashboard-landing-template.

Компоненты Button, Card, Input, Dialog, Tabs, Table, Sidebar, Sheet, Command, InputGroup и Kbd перенесены из шаблона в `app/admin/ui`, импорты адаптированы. Поиск разделов использует настоящий Command и `cmdk` 1.1.1; результаты ограничены правами сотрудника. Палитра и runtime-переменные радиусов сохранены в `template-theme.css`; состояния компонентов из `shadcn` 4.21.4 `tailwind.css` подключены через `template-utilities.css`. Лицензии MIT: `docs/shadcnstore-LICENSE.md` и `docs/shadcn-LICENSE.md`. Демонстрационные приложения, реклама и редактор темы не переносились. Next/React/NestJS/PostgreSQL сохранены.

Шапка имеет высоту 56 px, отступы рабочего пространства на компьютере — 24 px. Размеры кнопок, полей и иконок задаются вариантами компонентов шаблона, без общего принудительного размера; у малых кнопок восстановлен радиус 8 px. Меню аккаунта работает и в свёрнутой боковой панели. Фильтры находятся над таблицами с отдельной скруглённой рамкой. Главная использует структуру SectionCards, настоящий график последних семи дней и пять последних заказов: запросы и блоки графика/заказов требуют соответствующих прав. В персонале — меню действий строки, страницы, вкладки «Данные / Права доступа», закреплённые кнопки формы и карточки разрешений на мобильном экране. Подробная привязка к исходникам шаблона: [admin-template-alignment.md](admin-template-alignment.md).

Исходное состояние сохранено и отправлено **до реализации**: ветка `codex/pre-admin-redesign-20261012`, commit `ba59446d`. Работа находится в `codex/admin-redesign`.

## Запуск в тестовом окружении

```powershell
npm ci
npm --prefix server ci
npm --prefix server run build
# DATABASE_URL должен указывать на отдельную тестовую базу:
npm --prefix server run migration:run
npm --prefix server run dev
npm run dev
```

`NEXT_PUBLIC_API_URL` на frontend задаётся на этапе сборки и должен соответствовать API этого окружения. `FRONTEND_ORIGIN` backend должен включать адрес панели. Для production необходим HTTPS. Миграции добавляют таблицы и nullable-поле, не пересоздают каталог или заказы. Не запускайте seed на рабочей БД.

Для полностью изолированной проверки есть test-only harness, запрещающий исходящие запросы к интеграциям:

```powershell
$env:TEST_DATABASE_URL='postgresql://losos@localhost:55433/admin_redesign_test'
node server/test/prepare-admin-browser-test.cjs
node server/test/start-admin-browser-test.cjs
# В другом терминале:
$env:NEXT_PUBLIC_API_URL='http://127.0.0.1:4100/api'
npx next dev --hostname 127.0.0.1 --port 3102
```

Harness принимает только локальный адрес БД с `test` в имени. Создаёт тестовых сотрудников и явно помеченные тестовые заказы. Эти учётные записи и данные не предназначены для production и не импортируются рабочим приложением.

## Первый владелец

На backend временно задайте `ADMIN_BOOTSTRAP_ENABLED=true` и длинный случайный `ADMIN_TOKEN` (не менее 32 символов). В `/admin` появится «Создать первого владельца»: задайте имя, логин и пароль не короче 12 символов. Кнопка показывается только при разрешённой настройке и полном отсутствии сотрудников; сервер возвращает один boolean через `/admin/auth/bootstrap-status` без секретов. После создания выключите `ADMIN_BOOTSTRAP_ENABLED`. Для обычного входа используется только логин и пароль.

Общий `x-admin-token` больше не открывает рабочие API. Сотрудники входят индивидуально. Роли и permissions сохраняются в БД; браузер хранит только временный session token. Управление полномочиями доступно только владельцу. Подробности: `admin-security.md`.

## Миграции

- `1785010000000-AddAdminSecurity`: сотрудники, хеши сессий, журнал действий, ограничения попыток входа, редактируемые профили клиентов.
- `1785011000000-AddAdminNotifications`: события новых заказов в транзакции оформления, Web Push-подписки устройств.
- `1785012000000-AddOrderCategorySnapshot`: название категории в новых позициях заказа. Старым покупкам текущая категория не приписывается.

Права сверяются с актуальными данными на каждом серверном запросе. SSE перепроверяет доступ каждые две секунды. Отзыв доступа останавливает поток; блокировка/выход удаляет сессию и связанные push-подписки.

## Формулы отчётов

Время — Asia/Bishkek, UTC+6. Даты включают первый и последний выбранный день; SQL использует полуоткрытый интервал [начало первого дня, начало следующего дня). Сравнение — непосредственно предыдущий интервал той же длины.

Исторические `orders.createdAt` и `updatedAt` имеют тип `timestamp` без часового пояса. Отчёты интерпретируют их в текущем PostgreSQL `TimeZone`, соответствующем записи через `DEFAULT now()`. Для точного отображения этих дат через API часовые пояса Node.js и БД должны совпадать. Не меняйте исторический часовой пояс БД без миграции значений: переход на `timestamptz` требует явного преобразования из исходной зоны. Поле `completedAt` уже хранит часовой пояс.

- Заказы и статусы: заказы, созданные в выбранном городе и периоде, все статусы.
- Выручка: сумма сохранённого `total` заказов со статусом `completed`, завершённых за период. Для исторических записей без completedAt используется updatedAt; это ограничение старого учёта. Отмены исключены.
- Средний чек: выручка / количество завершённых заказов; при отсутствии завершений — 0.
- Дни и часы: тот же набор завершённых заказов, поэтому сумма графиков равна выручке.
- Товары и категории: quantity и lineTotal из неизменяемого снимка позиции. Это суммы до общей скидки заказа, а не распределение выручки. Категории старых заказов обозначены «не зафиксирована».
- Модификаторы: quantity и totalPrice из снимка; доплаты per-product учитывают количество блюд, per-line учитываются один раз.
- Комплектации: фактически сохранённые количества в заказе; отдельная выручка для бесплатной комплектации не придумана.
- Новый клиент: телефон с первым заказом в выбранном городе в этом периоде; повторный: первый заказ был раньше. Клиенты считаются уникально в периоде.
- Отмены: созданные в периоде заказы, сейчас имеющие статус cancelled.
- Действия персонала: только реально записанные ручные изменения статусов, с датой начала журнала; панель видна при наличии доступа к персоналу и журналу.
- Возвраты и прибыль: данные не собираются; значения не подменяются нулём. Себестоимость отсутствует.

Экспорт вызывает тот же серверный расчёт с теми же фильтрами. Пресеты периода применяются сразу; вручную изменённые даты остаются черновиком до «Применить». Пока даты не применены или отчёт загружается, экспорт недоступен. CSV защищён от формул в текстовых ячейках; блок сотрудников в нём требует тех же прав, что и экран. Большие списки товаров/заказов/клиентов/истории/сотрудников загружаются постранично.

## Уведомления, установка и обновление

Настройка VAPID, ограничения браузеров и работа offline описаны в `admin-notifications-pwa.md`. Без VAPID SSE и звук работают, но реальная внешняя Web Push-доставка недоступна. Ключи VAPID остаются на сервере. Сигнал требует действия пользователя: три пары нот общей длительностью три секунды, громкость по умолчанию 80%, ранее сохранённая громкость сохраняется. Одно событие звучит в одной вкладке сотрудника. Старые события после первого подключения не вызывают поток звуков.

PWA имеет отдельный service worker `/admin/sw.js` и scope `/admin`. В постоянный кэш попадают только публичные файлы, никаких заказов/PII/API/персонализированного HTML. Offline не ставит изменения в очередь. Обновление применяется только кнопкой пользователя с защитой несохранённой формы.

## Откат и выпуск

Production в ходе реализации не обновляется. Выпуск требует отдельного разрешения. Перед выпуском сохраните резервную копию БД и примените миграции на staging, создайте владельца и проверьте вход/интеграции. Для отката приложения доступен snapshot commit `ba59446d`; добавленные таблицы можно оставить. Не выполняйте обратные миграции с удалением рабочих таблиц сотрудников/журналов/подписок ради отката интерфейса.

Функциональная матрица: `admin-feature-parity.md`. Фактически выполненные проверки и снимки экранов: `admin-verification.md`.
