# Перенос административной панели

Дата сверки: 12 октября 2026 года. Исходная версия проекта: `ba59446d` (сохранение перед переработкой). Источники сверки: исходные `app/admin/*`, `server/src/admin/admin.controller.ts`, `admin.service.ts`, DTO, новые контроллеры отчётов, безопасности и уведомлений. Таблица описывает реализованный код; наличие строки не означает, что выполнена проверка на production.

## Основа интерфейса

Использован уже установленный пользователем шаблон `C:/Users/User/Desktop/admin`, репозиторий [ShadcnStore](https://github.com/shadcnstore/shadcn-dashboard-landing-template), commit `953300fa5176608a9d682943edfc359ce809f2c7`. Выбрана `nextjs-version`: текущий клиент использует React 19, Next.js App Router и совместимый путь сборки Vinext; NestJS/PostgreSQL-сервер сохранён. Компоненты шаблона на Base UI перенесены в `app/admin/ui`, тема — в `template-theme.css`; административный layout, навигация, карточки, таблицы, формы, диалоги и графики используют эту основу. MIT-лицензия сохранена в `docs/shadcnstore-LICENSE.md`. Демонстрационные Mail, Chat, Pricing, Landing и редактор тем не переносились.

Все пути API ниже указаны относительно `/api`. «Сверено по коду» означает проверку связи формы с существующим методом, серверным DTO и хранилищем. Результаты автоматических и браузерных прогонов записываются отдельно.

## Проверки и границы

- Подробные формулы каждого показателя, статусы, скидки, доставка и ограничения исторических данных приведены в `admin-redesign.md`, раздел «Формулы отчётов». Прибыль и возвраты не подменяются нулём, когда исходная модель не ведёт такой учёт.
- У исходных категорий нет отдельного признака активности или иерархии. Расписание хранит один общий временной интервал и набор рабочих дней; отдельные перерывы и исключения по датам в исходной модели не предусмотрены. Эти отсутствующие сущности не заявляются перенесёнными.
- Проверка границы UI/API дополнительно устранила перенос черновика комплектации на другой заказ при переходе из уведомления: черновик связан с исходным заказом, переход подтверждает сброс, устаревший ответ не открывает другую карточку. Формы блокируют изменение полей во время сохранения. Поиск и страницы топпингов доступны сотруднику с правом только просмотра.
- Существующие относительные ссылки акций сохраняются при редактировании других полей; новая или изменённая ссылка должна отвечать существующему API-контракту HTTP(S).
- В таблице нет утверждения о работе с production-базой, отправке реальных заказов или запуске экспортов в EDU POS. Внешние действия требуют отдельно настроенного окружения.
- Серверные проверки безопасности и уведомлений описаны в `admin-security.md` и `admin-notifications-pwa.md`; тестовое окружение изолировано. Проверки бизнес-логики находятся в `server/test` (backend, kits, promotions, city visibility, PostgreSQL integration).
- Старая история статусов и аудит отсутствовавших событий не выдумываются. Новые записи появляются после применения соответствующих миграций.
- Недоступного стороннего исходного кода не переносили: Яндекс Карты, push-службы браузеров и EDU POS остаются реальными внешними интеграциями. Их клиентские/серверные адаптеры сохранены.
- Проверка workspace-компонентов этой сверки: ESLint для `UsersWorkspace`, `SettingsWorkspace`, `CitiesWorkspace`, `CategoriesView`, `MenuWorkspace`, `PromotionsWorkspace`, `OrdersWorkspace`, `DeliveryZoneEditor`.
